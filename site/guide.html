Guide

How to use git-sea.

Every view, shortcut, gesture and menu, including the ones that are easy to miss: many things happen on a right-click, a ⇧-click or a key.

On Linux and Windows, Ctrl takes the place of ⌘ everywhere below.

The command palette

Press ⌘K anywhere. Almost everything git-sea can do is in it, so when you don't remember where something is, type a word: compare, replay, files, bookmark, theme.

  • Type a branch or tag name to jump to it, compare it with the selected commit, see what it brings over HEAD, or show only that branch.
  • Type two or more letters of a commit message, author or hash to jump to a commit.
  • It also switches views, tabs and themes, opens recent repositories, saves CI tokens and finds the commits of a type (Find the feat commits).

Tip: the palette lists the shortcut of each command next to it, which is the quickest way to learn them.

Opening repositories

  • ⌘O opens a folder; you can also drop a folder on the window.
  • From a terminal, git-sea opens the repository of the current folder and git-sea <path> the one at that path, in a new tab of the window already open. On macOS, install the command from the app menu, Install the git-sea Command….
  • Each repository is a tab. ⌘1–9 switch tabs (9 is the last one), ⌘W closes one, and you can drag tabs to reorder them. The open tabs come back the next time you start git-sea.
  • Recent repositories are in the palette: type their name.

Two repositories side by side

The split view button in the toolbar (a square cut in two), or a right-click on a tab, shows another repository below the current one. The palette can swap or close the two halves. Shortcuts act on the half you clicked last.

  • The minimap in the corner shows the whole history: click or drag in it to move there.
  • The follow button in the zoom controls keeps HEAD and the commits that arrive in view.
  • The zoom controls and the minimap have a grip: drag it to move them to another corner. They stay there in every view and tab.
  • The graph has levels of detail: cards with icons and messages up close, tiles further out, dots far away.
  • When a fetch brings commits you can't see, a pill like “3 new commits →” appears; click it to go to them.
  • b bookmarks the selected commit: it gets a ribbon, and its bookmark sits at the top of the sidebar and in the palette.
  • a lights up the ancestors of the selected commit (also the button with three dots in the toolbar).

Searching

Press /. Plain words look in the subject, the author and the start of the hash. Terms with a prefix narrow the search, and can be combined: login author:Anna after:2024-05 path:src.

PrefixFinds
author:commits by that author or co-author (names after .mailmap)
hash:commits whose hash starts so
msg:words anywhere in the whole message, not only the subject
path:commits that changed a file or folder, following renames
diff:commits that added or removed a text, like git log -S
after: before:dates: 2024, 2024-05, 2024-05-17, today, or a time ago such as 2w, 6m
re:a regular expression on subject and author
type: scope:Conventional Commits: type:feat, type:fix,docs, scope:ui
  • ↵ or ↓ goes to the next match, ⇧↵ or ↑ to the previous one. The other commits fade.
  • With the ancestors lit (a), the search looks only in the history of the selected commit.
  • Only one of msg:, path: and diff: per search: those read the repository, the others are instant.

Commit details

↵ shows or hides the details panel; drag its left edge to resize it. Besides message, author, co-authors and parents, it tells you:

  • Release: the oldest tag that holds the commit, and In: the branches that hold it.
  • The pull or merge request it belongs to, when the remote is on GitHub or GitLab.
  • For a merge, which parent the files are compared with: pick another one in Compared with.

Files and diffs

  • Click a changed file to see its diff, Unified or Split; changed words are marked inside the lines.
  • Blame shows, for each line, the commit that last changed it; click one to go there.
  • Hover a file to find the history button (a clock): it searches path: that file, renames included.

Local changes and CI

  • When the working copy has changes, HEAD's node gets a badge with their count: click it for the staged and unstaged diffs.
  • CI runs appear on the links of the graph. Click a marker for the runs of that commit; click a workflow in the sidebar to show only its markers.

Browsing the files

Browse the files, next to the changed files of a commit (or in the commit's right-click menu, or the palette), shows the whole tree of the repository as it was at that commit.

  • Type in the field to find a file by name, like an editor's “go to file”: the letters only need to be in order. ↑ ↓ and ↵ pick one.
  • A file shows with syntax colours, or as Blame; the clock button lists the commits that changed it.
  • The panel follows the selection: press j or k and you read the same file commit after commit.

Comparing

  • ⇧-click another commit (in any view) to compare it with the selected one. The older side is the base.
  • From the palette: compare the selected commit with HEAD, or with any branch or tag you type.
  • Right-click a branch in the sidebar for What it brings over HEAD: only the changes the branch made since it left, like git diff main...feature.

In the comparison panel, choose between The two trees (every difference) and From the common base (only what the newer side brings), and Swap the sides. The commits found on one side only are lit on the graph.

Next to a local branch with an upstream, the sidebar shows 4↑ 2↓: click it to light the commits ahead and behind.

The toolbar buttons

  • Colours by commit type (a tag icon) outlines the nodes by their Conventional Commits type, feat, fix, docs…, instead of by branch.
  • Flow sends dots along the links; the fish swim behind the graph. Both are only decoration and can be turned off.
  • The funnel chip shows the branch filter, and its × removes it.
  • ⌘B hides the sidebar.

Statistics

Press 4. Everything counts the loaded history, so it follows the branch filter.

  • Click an author to see only their activity in every card; the list button next to them shows their commits.
  • Click a day of the calendar for its commits.
  • Releases: each commit counts for the oldest tag that holds it. Click a release to compare it with the one before; click Not released to see what HEAD has that no tag holds.
  • Commit types: click a type or a scope for its commits.
  • Most changed files: click a folder to open it, a file for its commits. Rank by Commits or by Lines (counting lines reads every change, so the first time takes longer).
  • Changes over time: the same entries month by month; click a cell for the commits of that month.

The sidebar

  • Click a branch, tag, stash, bookmark or pull request to go to its commit. The field at the top filters the list.
  • The funnel on a branch (on hover) shows only that branch's history; others can be added to the filter.
  • Right-click a branch for what it brings over HEAD, comparisons and “show only this”.
  • Cleanup lists branches gone from the remote, branches whose upstream is gone or that have none, and branches already in HEAD. git-sea never deletes them: each group has a Copy the command button to run it yourself. It asks the remotes only while the group is open.
  • Drag the sidebar's edge to resize it; double-click the edge to get the default width back.

Right-click menus

On a commit, in any view

  • Copy the hash, the short hash or the whole message.
  • Compare with the selected commit; add or remove a bookmark.
  • Browse the files of the commit.
  • Replay the history from here, or up to here (graph and topology).
  • Open the commit on GitHub, GitLab, Bitbucket or Azure DevOps.

On a branch or a tag in the sidebar

  • What it brings over HEAD or over the selected commit, from the common base.
  • Compare it with HEAD; show only this branch.

On a tab

  • Show another repository alongside, in the split view.

Images and replays

The last button of the zoom controls, in the graph, topology and timeline:

  • Save as PNG or Copy as image: the view as it is on screen, sharper than the screen.
  • Replay the history (graph and topology): the history grows commit by commit. Pick where it starts and ends and the speed, then save it as a GIF or a video. Space plays and pauses, Esc closes.

Settings

⌘, opens them:

  • Language (English or Italian) and theme (system, light, dark).
  • Pause the animations while the window is in the background.
  • The graph cache on disk, which makes large repositories reopen at once, and a button to clear it.
  • The terminal command on macOS.

CI and pull requests use the gh and glab logins when they're there; otherwise save a token from the palette (token), and it goes to the Keychain, the Secret Service or the Credential Manager. Remote branches are fetched in the background every few minutes; the status bar says when, and has a button to fetch now.
